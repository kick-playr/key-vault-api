# APP-35 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task in this session. The user requested continued implementation.

**Goal:** Deliver the NestJS local development vault and tenant-safe runtime client described in APP-35.

**Architecture:** Nest controllers authenticate exact namespace grants and delegate to a transactional encrypted store and manifest reconciler. A server-only client publishes complete expiring snapshots before consumer initialization.

**Tech Stack:** NestJS, TypeScript, Node 22+, built-in crypto/fs, Jest and Supertest.

**Spec:** `docs/superpowers/specs/2026-11-01-app-35-design.md`

## Global constraints

- Loopback only; no unauthenticated vault access or plaintext persistent secrets.
- Azure data-plane subset pinned to 2025-07-01; document deviations.
- Private keys never leave crypto service; tenant snapshots never modify process.env.
- Reconciliation must reuse existing encryption keys and commit atomically.
- No live credentials, migration or deployment.

## Review focus

- Malformed nested JSON and unsupported options must fail safely, with no partial mutations.
- Store write failure must leave previous memory/disk state intact.
- Namespace and deterministic-name collisions must not expose another tenant's material.
- Out-of-order revisions, concurrent restarts and refreshes must not rotate keys or roll back snapshots.
- Disabled/expired/deleted values must not be served from indefinite caches or regenerated by ordinary reconciliation.
